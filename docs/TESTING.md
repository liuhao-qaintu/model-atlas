# 测试与评测

验证分为功能回归、检索对照和回答评审。三类结果回答不同问题，应分别记录模型配置、资料范围、题集和复核方式。

| 检查类型 | 主要问题 | 结果用途 |
| --- | --- | --- |
| 功能回归 | 账号隔离、解析、引用和会话行为是否符合约定？ | 检查实现与交互边界 |
| 检索对照 | 改变检索方案后，相关资料是否更容易被找到？ | 比较召回与排序 |
| 回答评审 | 回答是否正确、完整并得到对应正文支持？ | 识别生成、证据和解释问题 |

## 后端回归

从 `model-rag` 根目录使用项目 Python 环境运行：

```powershell
& '.\.venv\Scripts\python.exe' -B tools/run_tests.py
```

该入口使用临时数据目录和 SQLite，阻止外部 HTTP 请求，不重建或清理业务 MySQL。单用户业务测试使用真实 JWT 夹具，多用户边界检查直接运行生产认证中间件与按用户检索注册表。

检查涵盖账号归属、会话、解析、规划、图关系、引用、资料范围和回答约束等。未安装可选论文原文或原图时，对应素材检查跳过；不能把这些结果当成真实模型的回答准确率。

## 前端回归

进入 `model-rag/frontend` 执行：

```powershell
node --test tests/*.test.js
npm.cmd run build
```

这些检查覆盖流式协议、导航、引用、追问、账号存储分区和 CSRF 辅助逻辑。页面外观与完整使用过程仍需在实际浏览器中检查。

## 检索对照

维护入口提供纯向量、混合检索与混合检索加图谱扩展的对照。比较时固定资料、规划、向量和标注池，避免把资料变化误认为检索方案变化。

| 指标 | 关注的内容 |
| --- | --- |
| Hit@5 | 前五个结果是否至少包含一项已知相关证据 |
| Recall@5 | 前五个结果覆盖了多少已标注的相关证据 |
| Precision@5 | 在标注完整时，前五个位置中相关结果的比例 |
| Returned precision | 实际返回结果中相关证据的比例 |
| Reciprocal rank | 第一条相关结果出现在什么位置 |

当前标注对象主要是正文片段，不能直接与其他项目按文档计算的数字比较。存在未判断结果时，精确率保留未知或给出上下界；检索得分未经概率校准，不作为答案置信度。

## 回答评审

先获取完整回答，再按照题目标准记录正确、部分正确或错误。模型建议、助手标注和用户人工复核分别保留来源；只有相应复核结果才能支持对应统计。

除结论外，还应检查：

- 是否理解当前问题的对象、指代和资料范围。
- 是否覆盖问题实际要求的条件、输入输出或比较维度。
- 引用正文是否支持相邻结论，而不仅是编号可以打开。
- 是否区分论文记载、教学示例和有前提的推导。
- 缺少证据时是否保留缺口，避免把未检索到写成全文不存在。

开发题集的标注来源、适用范围及人工复核状态保存在题目字段中。开发题集得分不等于独立盲测结论，也不能用同模型复核直接证明不存在错误。

## 人工验收建议

用同一账号完成“学模型 → 导入相关论文 → 比较方法 → 连续追问 → 打开引用”的过程，并核对以下结果：

1. 提问能关联到当前模型或所选文献，追问对象没有被应用领域替换。
2. 阅读报告、标签和引用能对应导入资料；正文未提供的细节没有被编造。
3. 比较结果能分别找到双方依据，继续追问仍在同一会话内。
4. 仅本地处理的资料未进入远程模型请求。
5. 换用另一个账号后，不能读取前一账号的文献、报告和会话。

真实模型能力需要在允许云端处理的资料和可用模型配置下另行检验。未经实际运行与复核，不在项目介绍中填入准确率、幻觉率或延迟数字。
