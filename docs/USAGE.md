# 使用流程

Model Atlas 的三个主要入口分别用于学习模型、管理本人文献和比较资料。可以从模型原理开始，也可以从一篇已经在阅读的论文开始；连续问答用于在这些内容之间继续查证。

## 选择一个起点

| 当前需求 | 从哪里进入 | 建议的第一步 |
| --- | --- | --- |
| 对模型不熟悉 | 学模型 | 先看输入输出，再看结构、公式和代码 |
| 已经有一篇论文 | 我的文献 | 导入资料，核对解析信息和阅读报告 |
| 想比较不同方法 | 比较研究 | 明确比较对象和维度，再选择资料范围 |

## 学模型与章节提问

登录后打开 AE、CNN、Transformer 等模型条目，按需要选择章节：

- **概览与结构**：了解模型处理什么问题、采用哪些核心模块。
- **输入输出**：检查数据类型、维度和输出的实际含义。
- **公式与解读**：结合符号、前提和运算过程理解定义。
- **代码实现**：对照教学代码阅读数据流，区分示例设置与论文设置。
- **模型关系**：查看相关模型、模块及支撑联系的资料。

使用章节中的提问入口，可将当前模型或章节带入问答。引用编号对应本轮使用的正文，展开后可以核对节选、来源和可用的定位信息。

教学例中的潜在表示、特征和类别分数有不同含义。理解结构时应同时看输入、目标和输出用途，不能只凭维度数量判断模型在做什么任务。

## 导入与阅读文献

在“我的文献”选择 PDF、Markdown 或文本文件，预览解析结果后导入。该列表只包含当前账号上传或导入的资料，可按标题、文件名和标签查找。

```mermaid
graph LR
    A["选择文件"] --> B["核对解析信息"]
    B --> C["导入个人文献"]
    C --> D["获准后生成分析报告"]
    D --> E["确认标签与关系"]
    E --> F["参与后续检索"]
```

### 先确定处理范围

仅本地处理的资料用于本地解析和检索。允许云端处理后，相关内容才能用于远程嵌入、重排、阅读报告和回答生成；是否启用这些能力还取决于本地模型服务配置。

### 阅读报告，核对重要结论

切片在后台处理，阅读重点放在整篇报告：文章讨论什么、采用什么方法、有哪些贡献、涉及哪些模型与知识，以及相应依据在哪里。标签和关系确认后才进入后续管理流程。

PDF 文字提取不等于还原原始排版。页码、章节和解析段落用于帮助定位；解析段落编号不保证与出版社版式中的段落编号一一对应。公式、图表和实验设置应打开原文件核对，扫描件需先进行 OCR。

文献版本与检索优先级可按使用需求管理。调整优先级会影响检索排序，不会使资料中的结论自动变得更可靠。

## 连续提问与资料范围

同一会话可以继续追问。当前问题、页面选择和近期交流共同用于确定对象；旧回答只帮助理解上下文，不作为新的事实来源。

| 提问方式 | 使用范围 |
| --- | --- |
| “只根据这篇论文，作者采用了什么结构？” | 只核对所选资料，保留未说明的部分 |
| “论文只提到 ResNet，帮我解释它的一般机制。” | 允许补查时，可使用其他获准资料解释模型原理 |
| “刚才这个结论的依据在哪里？” | 结合本会话对象和本轮正文继续定位 |

补充资料解释的是一般机制或其明确版本。不能因为某个模型通常采用一种结构，就声称所选论文也采用该结构。

## 比较研究与后续追问

提出包含对象和维度的问题，例如比较输入表示、训练目标、结构或输出。选择可用于云端处理的资料后，系统拆解查证项、查找正文，并按证据缺口继续补查。

返回结果附带引用和缺口说明。对于完整完成的研究结果，可以进入其对应会话继续问答，不必重新组织全部背景。

如果问题涉及论文没有报告的实验结论，结果可能保留该缺口。基于原理的条件推导与论文实测应分开阅读。

## 模型关系与个人资料

关系页面用于查看模型、方法与资料之间已有依据的联系。自建模型和关系属于当前账号；分析报告中的建议需核对后确认。关系证据用于说明联系，不直接证明因果、适用性或性能优劣。

共享模型资料通过模型条目和问答引用按需查看，不会挤入“我的文献”列表。

## 维护入口

维护工具需要管理员角色和本地维护白名单，用于关系审核、检索对照与回答评审。业务管理员也不能默认查看其他用户的私有资料。

机器建议与人工复核分别记录。评测入口的使用方式见[测试说明](TESTING.md)，不需要在普通阅读与问答中操作这些工具。
